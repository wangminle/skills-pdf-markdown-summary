## 发现 2：邻块吸收突破跨栏、排除区和真实行边界（P2，BUG-146）

位置：[`lib/equation_regions.py:201`](../../skills/pdf-markdown-summary/scripts/lib/equation_regions.py#L201)、[`209`](../../skills/pdf-markdown-summary/scripts/lib/equation_regions.py#L209)、[`300`](../../skills/pdf-markdown-summary/scripts/lib/equation_regions.py#L300)。

三个已复现的独立反例：

- 双栏范围 `[40,200]` / `[209,369]`，左栏公式 `[130,100,200,112]` 与右栏正文 `[209,100,250,112]`。候选的双栏判据认为 9pt 栏间距合法；吸收只检查邻块在其自己的栏内，没有核对它与公式属于同一栏，最终把 `Right prose.` 加入公式。主放置助手 images=off 时正文实际被收进公式代码块。
- 同栏两式 y100–112 / y130–142，中间有正文 y116–128。分组跨过该正文；吸收以整个组的总 bbox 判“同一视觉行”，把 `This is ordinary prose.` 也收进公式，而该正文与两条公式行都不重叠。

## 发现 3：包含简单赋值的短正文会误判成独立公式（P2，BUG-147）

位置：[`lib/equation_regions.py:74`](../../skills/pdf-markdown-summary/scripts/lib/equation_regions.py#L74)。存在等号便允许句点结尾，再叠加符号比例和缩进就会通过。例如正常宽正文栏 `[40,360]` 内的短句 `We set a=1.`，bbox `[70,100,180,112]`，被判为独立公式；主放置助手 images=off 实际将其替换为公式代码块，images=figures 会把正文替换成公式图片。

这是文档宣称“宁可漏检，不可把正文误检为公式”的防护缺口。应结合自然语言句式/文本结构判断独立公式，而不是只依赖一个等号和窄块几何；补短正文负例并保留真实原生公式正例。此为合成反例，不主张三篇原 PDF 已发生该误检。

## 发现 4：A3 重渲染失败删除旧图，却报告保留旧结果（P2，BUG-148；BUG-142 重新打开）

位置：[`lib/pipeline.py:455`](../../skills/pdf-markdown-summary/scripts/lib/pipeline.py#L455)、[`729`](../../skills/pdf-markdown-summary/scripts/lib/pipeline.py#L729)、[`lib/output.py:44`](../../skills/pdf-markdown-summary/scripts/lib/output.py#L44)。

构造真实 PDF、已有有效 PNG、accepted 记录和真实候选框，只将精修器结果设为确定可接受框，并对 `Pixmap.save` 注入“截断目标为 0 字节后抛 I/O 异常”的行为。实际进入 A3 重渲染分支后：

- `save_pixmap_clean` 对原 PNG 路径直接保存，清理掉该路径；
- PNG 从存在有效图片变为不存在；
- pipeline 只回滚元数据，记录仍 accepted，bbox 恢复旧框；
- 报告 `kept_legacy=1`、reason=`rerender failed, kept legacy`；
- A3 没有将硬失败送进主入口的 render_failures 列表。

因此“五个渲染出口已统一硬失败传播”的收尾说明不准确。应先在临时文件成功渲染，再原子替换旧图；失败时保留旧 PNG 及其哈希，传播硬失败。若约定保留旧图后允许降级，则必须确实保留可用图片并如实报告该状态。

证据：`a3-counterexample.json`，含原 PNG SHA256、png_exists=false、accepted 记录与实际 A3 report。此问题触发条件是启用 Layout/A3 且重渲染 I/O 失败；本轮正常三篇转换没有触发。原先重渲染直接写旧文件也有风险，新增清理使零字节文件变成缺失文件，但没有完成真正的回退。
