# PDF 功能模块全集与编号

本目录是 **2026-09-30 当前工作区**代码的功能拆解（包含尚未提交的业务修改）。功能模块按“一个明确能力或策略边界”划分，**不是按 Python 文件、函数个数或未来重构组件划分**。一个大函数可以承担多个功能；多个函数也可以共同实现一个功能。

- `Fxx`：功能域；`Fxx.nnn`：域内功能模块的正式编号。功能域不是额外计入总数的子功能。
- 编号一经发布保持身份；新增只在对应域尾部追加；删除功能标记弃用，不复用编号；重命名保持原 ID。不要因文件移动、展示顺序变化或新功能插入而整体重排。
- 一份模块可以有多个实现引用；共享助手可支撑多项能力。嵌套助手继承所属父函数/类编号；纯包/兼容导出层不把被导出的运行能力再算一遍。
- “默认”描述推荐 robust 主路径中按条件参与的能力，不保证每个资产都触发；“可选”需开关/参数；“底层备用”可调用但未接主流程；“数据契约/占位/兼容”不等于已具备端到端输出。
- 最终 Agent 阅读摘要另标为 `EXT-01`，它是 Skill 的文本+图像阅读/写作行为，不在这些 Python 已实现功能数量中。

共 **397 个编号功能模块**：正式实现 **337 个**（54 个 Python 文件），测试/评测保障 **60 个**（35 个 Python 文件）。源码定义（包括顶层、类方法、嵌套和条件分支）**1316 个，全部有功能归属**。这个覆盖检查不能证明每条运行分支正确或功能有效。

可执行范围包括正式 `scripts/`、版本化 `tests/scripts/` 与 `tests/eval/`。历史归档、只读参考、测试结果、标注数据和一次性实验不作为维护能力；仓库 package.json 是空对象，无独立 JS 工作流。

## 主处理链上的关键界限

- 四个 CLI 包装进入 core；process 先 Markdown 成功再摘要材料复用。summarize 只准备/核对材料并提示路径，最终摘要由 EXT-01 撰写。
- 纯文本与结构化正文不同；结构化文本内部的 caption/list/body 判别并未完整进入 GatheredParagraph 对外标签，只保存标题布尔值等当前字段。
- 基础字体/栏位模型与语义 Layout 后端分开。语义区域提前提取，但默认 Figure/Table 不接收 layout_result；A1 的引用过滤是报告统计，不直接修改正式 records；候选种子函数未直接成为默认提取输入。
- 可选后精修发生在图表上下文之后、题注对账及 index 之前。不通过守卫保留原几何；原 rejected/review 状态不会仅因几何微调自动升级。
- AttachmentRecord 的 None 是初始缺证据状态。正式链 apply_assessment 已写入启发式 pairing/boundary 置信度，续表/缺口也设置证据；它们不是校准概率或完整统计评分模型。
- PDF 底层的备用表格 helper 与 Markdown 的 `--tables structure` 不构成已接通的结构化表格输出；OCR 参数也没有执行 OCR。
- 正式质量判断和测试评测是两套不同职责；golden 是变更检测器，不能当正确性 GT。评测器的贪心匹配也不是正式 pipeline 的最优匹配算法。
