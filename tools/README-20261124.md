# tools/ 使用说明

仓库维护脚本，纳入版本控制。它们不是 PDF Skill 的实现，不纳入功能编号；运行产物一律写入已被 gitignore 的 `experiments/`，不要写进本目录。所有脚本都在仓库根目录运行，各脚本开头的说明有完整参数。

## feature-registry/：功能编号资料与三张 SVG

| 脚本 | 作用 |
| --- | --- |
| `verify_numbering_dynamic_20260930.py` | 校验功能编号三件套与源码、SVG 是否一致：编号唯一、源码哈希与行号、声明归属、文档链接、SVG 是合法 XML。退出码非 0 即不通过。按 `AGENTS.md` 第 9 节，每次改动编号资料后都要跑。 |
| `draw_feature_index.py` | 读取编号表 JSON，重生成 `design/4-analysis/` 下的三张 SVG（它会连带执行同目录的 `draw_flows.py`）。功能、数量、分组或流程关系变化后运行，改完看一眼渲染结果。 |
| `draw_flows.py` | 生成脚本协作泳道图与图表提取展开图。泳道图左上角的落款（版本与日期）是写死的，版本升级时先改这一处再重生成。 |

```bash
python3 tools/feature-registry/verify_numbering_dynamic_20260930.py
python3 tools/feature-registry/draw_feature_index.py
```

两样东西仍然只在本地：

- 各轮的编号同步脚本（把源码变化机械写进编号表 JSON、覆盖索引与全集 md）留在 `experiments/sync-numbering-20260930/`，每轮一份，没有入库。新机器上要同步编号时，以最新一份为底稿。不要手写编号表 JSON。
- [PDF脚本协作图阅读说明](../design/4-analysis/PDF脚本协作图阅读说明-20260930.md)是人工维护的，没有可用的生成脚本。

## render-probe/：渲染特征探测（架构收敛 WP-1.1）

| 脚本 | 作用 |
| --- | --- |
| `probe_render_features.py` | 对 8 份 Basic Benchmark PDF 做只读探测：书签、粗体、字号、通栏分布、分阶段耗时。产出 `probe_results.json` 与简报 `probe_brief.md`。含两种模式的耗时时完整跑一遍约 10 分钟。 |
| `probe_dict_call_reuse.py` | 统计一次转换里每页的 `get_text`、`get_drawings` 被重复解析了几次。约 3 分钟。 |

```bash
python3 tools/render-probe/probe_render_features.py --no-timing
python3 tools/render-probe/probe_dict_call_reuse.py
```

两个脚本只读 `tests/basic-benchmark/`，运行前后核对 8 份 PDF 的哈希，有变化即判失败。产物默认写入 `experiments/arch-convergence-probe-20261124/`，可用 `--out-dir` 改到别处。

2026-11-24 的结论见[架构收敛WP-1.1渲染特征探测简报](../design/4-analysis/架构收敛WP-1.1渲染特征探测简报-20261124.md)。要留档新的探测结果，把简报另存为带日期后缀的快照放进 `design/4-analysis/`；旧简报的解读只对应当时的测量。
