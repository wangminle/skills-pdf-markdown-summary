# PDF 图表提取流程逻辑说明

> 日期：2026-06-21
> 范围：当前正式 Skill 目录 `skills/pdf-markdown-summary/scripts/lib/` 中 Figure/Table 提取相关代码。
> 主要入口：`extract_figures.py::extract_figures()`、`extract_tables.py::extract_tables()`。
> 关键依赖：`caption_detection.py`、`direction.py`、`refine.py`、`layout_model.py`。

## 1. 总体架构

Figure 和 Table 共用一条主干流水线：先找到可信 caption，再决定图表在 caption 上方还是下方，然后生成 baseline 窗口，依次执行文本裁切、对象对齐、X 方向收窄、版式约束、像素 autocrop、最终验收和保存。

Table 在主干上增加了更多表格专用保护：多行表头回收、渲染横线补偿、表格行带识别、表格宽度恢复、文本 bbox 安全补边、远端章节标题裁除。

```mermaid
flowchart TD
    A["开始：extract_figures / extract_tables"] --> B["解析用户参数：强制方向、no_refine、阈值"]
    B --> C{"启用 smart_caption_detection？"}
    C -->|是| D["build_caption_index：全文预扫描 caption 候选并评分"]
    C -->|否| E["跳过 caption 索引"]
    D --> F{"启用 adaptive_line_height？"}
    E --> F
    F -->|是| G["estimate_document_line_metrics：估计典型行高并调整距离阈值"]
    F -->|否| H["使用默认阈值"]
    G --> I{"global_anchor 为 auto 或 None？"}
    H --> I
    I -->|是| J["compute_global_anchor：累计 above/below 得分，生成全局方向锚点"]
    I -->|否| K["使用传入的 global_anchor"]
    J --> L["逐页扫描 PDF"]
    K --> L
    L --> M["收集 text_lines、draw_items、image_rects、vector_rects"]
    M --> N["逐文本行匹配 Figure/Table caption 正则"]
    N --> O{"候选是否有效？"}
    O -->|否| N
    O -->|是| P["caption 过滤、合并、命名、方向判定"]
    P --> Q["生成 baseline"]
    Q --> R["Phase A：文本裁切"]
    R --> S["Phase B：对象对齐"]
    S --> T["X 方向列感知收窄"]
    T --> U["Layout 版式约束"]
    U --> V["Table 专用行带/尾部恢复"]
    V --> W["Phase D：autocrop"]
    W --> X["Figure/Table final 专用后处理"]
    X --> Y["refine_safe 验收"]
    Y --> Z{"通过？"}
    Z -->|否| AA["拒绝候选或回退 Phase A / baseline"]
    Z -->|是| AB["保存 debug visual"]
    AA --> AB
    AB --> AC["按 final_clip 渲染 PNG 并记录 AttachmentRecord"]
    AC --> N
```

## 2. 预处理阶段

### 2.1 参数集合

两个入口都会先把用户传入的强制方向和跳过精裁参数转成集合：

- Figure：`below_figs`、`above_figs`、`no_refine_figs`。
- Table：`t_below`、`t_above`、`no_refine_tables`。

后续所有精裁阶段都会检查 `ident not in no_refine_set`。如果某个编号在 no-refine 集合内，它仍会按 baseline 保存，但跳过 Phase A/B/X/layout/autocrop/final 后处理等精裁步骤。

### 2.2 CaptionIndex 预扫描

启用 `smart_caption_detection` 时，会调用 `build_caption_index()`：

```mermaid
flowchart TD
    A["build_caption_index(doc)"] --> B["逐页提取图像和绘图对象"]
    B --> C["find_all_caption_candidates：按 Figure/Table 正则找候选"]
    C --> D["score_caption_candidate"]
    D --> E["位置得分：离图像/绘图对象越近越高"]
    D --> F["格式得分：粗体、独立行、冒号/句点等"]
    D --> G["结构得分：下一行描述、段落长度"]
    D --> H["上下文得分：caption 语义加分，正文引用扣分"]
    E --> I["写入 CaptionIndex：figure_N / table_N -> candidates"]
    F --> I
    G --> I
    H --> I
```

实际扫描到某个 caption 行后，还会用 `caption_index.get_best_for_page(kind, ident, page, min_score=25)` 做二次过滤：

- 如果同页没有得分足够高的最佳候选，跳过。
- 如果当前行与最佳候选的 y 距离大于 `30pt` 或 x 距离大于 `50pt`，跳过。
- 这样可以排除正文里的 “see Figure 3” 或 “Table 4, we compare...”。

### 2.3 自适应行高

启用 `adaptive_line_height` 时，`estimate_document_line_metrics()` 会估计 `typical_line_h`，并用它调整：

- `adjacent_th = 2.0 * typical_line_h`
- `far_text_th = 15.0 * typical_line_h`
- `text_trim_gap = 0.5 * typical_line_h`
- `far_side_min_dist = 3.0 * typical_line_h`

这些阈值直接影响 Phase A 文本裁切、远端正文检测和 Table 行带识别。

### 2.4 全局方向锚点

当 `global_anchor` 或 `global_anchor_table` 为 `auto/None` 时，会调用 `compute_global_anchor()`：

```mermaid
flowchart TD
    A["compute_global_anchor"] --> B["遍历文档内所有 caption"]
    B --> C["分别构造 above_clip 和 below_clip"]
    C --> D["score_direction_for_caption"]
    D --> E["墨迹密度得分：estimate_ink_ratio"]
    D --> F["对象覆盖得分：compute_object_ratio"]
    E --> G["累计 above_total / below_total"]
    F --> G
    G --> H{"above_ratio 是否 > 0.5 + margin？"}
    H -->|是| I["全局锚点 = above"]
    H -->|否| J{"below_ratio 是否 > 0.5 + margin？"}
    J -->|是| K["全局锚点 = below"]
    J -->|否| L["全局锚点 = None"]
```

全局锚点只作为低置信局部方向的 tie-break，不会覆盖强局部证据。

## 3. Caption 扫描与候选过滤

页面扫描流程如下：

```mermaid
flowchart TD
    A["逐页读取 page.get_text(dict)"] --> B["collect_text_lines"]
    A --> C["collect_draw_items"]
    C --> D["Figure：收集 orient=O 的 vector_rects"]
    C --> E["Table：收集 H/V/O 的 vector_rects"]
    A --> F["收集 type=1 图像块为 image_rects"]
    F --> G["遍历文本 block 和 line"]
    G --> H{"是否匹配 FIGURE_LINE_RE / TABLE_LINE_RE？"}
    H -->|否| G
    H -->|是| I{"is_caption_reference？"}
    I -->|是| G
    I -->|否| J["extract_figure_ident / extract_table_ident"]
    J --> K{"编号是否有效且未被重复处理？"}
    K -->|否| G
    K -->|是| L{"CaptionIndex 是否允许此候选？"}
    L -->|否| G
    L -->|是| M["merge_caption_lines 合并多行 caption"]
    M --> N["build_output_basename 生成输出文件名"]
```

Figure 还会检查 `min_figure/max_figure` 范围；Table 当前没有对应编号范围检查。

`allow_continued=False` 时，同一编号只处理第一次；如果允许 continued，则后续同编号会标记 `continued=True`。

## 4. 方向判定逻辑

方向判定分为局部方向评分、最终方向决策和 Figure 裸 caption 特殊纠偏。

```mermaid
flowchart TD
    A["score_local_direction"] --> B{"是否 Table 且有 text_lines？"}
    B -->|是| C["计算 above/below 表格文本特征"]
    C --> D["短文本比例、宽长正文比例、结构化行距离、结构化行数量"]
    D --> E{"上下都有结构化行且下方有后续 caption，且上方更近？"}
    E -->|是| F["返回 above, 0.62：解决上下两表夹 caption"]
    E -->|否| G{"文本方向分差 >= 0.03？"}
    G -->|是| H["返回得分较高方向，置信度 >= 0.60"]
    G -->|否| I{"结构化行距离有明显近邻？"}
    I -->|是| J["返回更近方向，置信度约 0.60-0.72"]
    I -->|否| K["进入对象覆盖率判断"]
    B -->|否| K
    K --> L["构造 above_clip / below_clip"]
    L --> M["计算对象覆盖率 obj_above / obj_below"]
    M --> N{"对象覆盖总量很低？"}
    N -->|是| O["默认：Figure above，Table below，置信度 0.5"]
    N -->|否| P{"above_ratio > 0.6？"}
    P -->|是| Q["返回 above"]
    P -->|否| R{"below_ratio > 0.6？"}
    R -->|是| S["返回 below"]
    R -->|否| O
```

`determine_direction()` 的最终优先级：

```mermaid
flowchart TD
    A["determine_direction"] --> B{"编号在 forced_below？"}
    B -->|是| C["below"]
    B -->|否| D{"编号在 forced_above？"}
    D -->|是| E["above"]
    D -->|否| F{"local_evidence 置信度 >= 0.6？"}
    F -->|是| G["采用局部方向"]
    F -->|否| H{"页面位置启发式触发？"}
    H -->|Table caption 在页面底部 25%| I["above"]
    H -->|Figure caption 在页面顶部 1/3| J["below"]
    H -->|未触发| K{"有 global_anchor 且局部置信低？"}
    K -->|是| L["采用 global_anchor"]
    K -->|否| M{"无局部证据但有 global_anchor？"}
    M -->|是| L
    M -->|否| N["默认：Figure above，Table below"]
```

Figure 额外调用 `correct_bare_figure_caption_direction()`：

```mermaid
flowchart TD
    A["correct_bare_figure_caption_direction"] --> B{"当前方向是否 below？"}
    B -->|否| Z["保持原方向"]
    B -->|是| C{"caption 文本是否裸 Figure N？"}
    C -->|否| Z
    C -->|是| D{"下方是否有下一张 Figure caption？"}
    D -->|否| Z
    D -->|是| E{"caption 上方近处是否有图像/矢量对象证据？"}
    E -->|是| F["方向改为 above"]
    E -->|否| Z
```

## 5. Baseline 窗口生成与版式预限制

基础窗口由 caption、方向、固定高度和左右 margin 决定：

- `direction == above`：从 `caption_bbox.y0 - gap` 向上取 `clip_height/table_clip_height`。
- `direction == below`：从 `caption_bbox.y1 + gap` 向下取固定高度。
- X 范围先取页面左右 margin 内的整宽区域。

之后会逐步限制或补回 baseline：

```mermaid
flowchart TD
    A["生成 base_clip"] --> B{"有 CaptionIndex？"}
    B -->|是| C["limit_clip_by_neighbor_captions：用同类相邻 caption 限制远端边界"]
    B -->|否| D["跳过相邻 caption 限制"]
    C --> E{"有 layout_model？"}
    D --> E
    E -->|是| F["收集 paragraph/list/title text_blocks"]
    F --> G["limit_clip_by_text_blocks：用远端正文/标题 blocker 收紧 baseline"]
    E -->|否| H["跳过 layout text block 限制"]
    G --> I{"当前是 Figure？"}
    H --> I
    I -->|是| J["expand_clip_to_nearby_figure_title：回收被 blocker 裁掉的图内标题"]
    I -->|否| K["expand_clip_to_nearby_table_header：回收被 blocker 裁掉的多行表头"]
    K --> L["expand_clip_to_rendered_horizontal_rule：Table 近 caption 侧补回渲染横线"]
    J --> M["clip = base_clip"]
    L --> M
```

`limit_clip_by_text_blocks()` 的关键判断：

- 只限制远离 caption 的一侧，不动近 caption 边。
- 双栏窄 caption 会先判断文本块是否与当前栏相关。
- 短标题、数字短行、无句末标点短行更像图表内部内容，优先保护。
- 宽正文、长段落、孤立标题更像 blocker，用来裁掉远端正文或下一节标题。

## 6. Phase A：文本裁切

如果 `text_trim=True` 且编号不在 no-refine 集合内，执行 `trim_clip_head_by_text_v2()`。

```mermaid
flowchart TD
    A["Phase A：trim_clip_head_by_text_v2"] --> B["先调用 trim_clip_head_by_text：裁近 caption 侧相邻正文"]
    B --> C{"有 typical_line_h？"}
    C -->|是| D["Phase A+：检查近端条带是否恰好两行正文"]
    C -->|否| E["跳过 exact-two-lines"]
    D --> F{"两行是否是 caption 本身？"}
    F -->|是| E
    F -->|否| G["按两行文字边界进一步裁近端"]
    G --> H["Phase B 文本：检测 adjacent_th 到 far_text_th 范围内远距离正文"]
    E --> H
    H --> I["计算近端段落覆盖率"]
    I --> J["Phase C：检测远端半区大段落"]
    J --> K{"远端正文覆盖率 >= far_side_para_min_ratio？"}
    K -->|是| L["向内推远端边界，并可做邻近短行清扫"]
    K -->|否| M["保持当前 clip"]
```

Table 调用该函数时设置 `skip_adjacent_sweep=True`，避免清扫逻辑误伤表头或表格内部短行。

## 7. Phase B：对象对齐

如果未 no-refine，执行 `refine_clip_by_objects()`：

```mermaid
flowchart TD
    A["Phase B：refine_clip_by_objects"] --> B["筛选与 clip 相交且面积比例达标的 image/vector 对象"]
    B --> C{"没有候选对象？"}
    C -->|是| Z["返回原 clip"]
    C -->|否| D["merge_rects 合并相近对象"]
    D --> E["选择最靠近 caption 的组件"]
    E --> F{"use_axis_union 且多个组件纵向重叠？"}
    F -->|是| G["合并垂直堆叠组件"]
    F -->|否| H["保持 chosen"]
    G --> I{"Table 使用 use_horizontal_union？"}
    H --> I
    I -->|是且横向并列重叠| J["合并水平并列组件"]
    I -->|否| K["查找 nearby short labels"]
    J --> K
    K --> L["把贴近对象的短标题/轴标题合入 chosen"]
    L --> M{"near_edge_only？"}
    M -->|否| N["直接返回 chosen ∩ clip"]
    M -->|是| O["只调整靠近 caption 的 y 边，x 可按对象扩展"]
    O --> P{"裁边会丢小对象带或文本标签带？"}
    P -->|是| Q["保留原 near edge"]
    P -->|否| R["采用对象边界"]
    Q --> S{"near-caption 图内标注保护触发？"}
    R --> S
    S -->|是| T["局部补回子图说明、Prompt 文本等"]
    S -->|否| U["返回结果"]
    T --> U
```

Figure 和 Table 的参数差异：

- Figure：`use_horizontal_union=False`，更偏向图主体对象。
- Table：`use_horizontal_union=True`，便于合并横向并列的表格线和单元格区域。
- Figure 传入 `text_lines`，用于保护竖排标签、低字号图内短标题和 near-caption 图内标注。

## 8. X 方向列感知收窄

`refine_clip_x_range()` 只改 X 范围：

```mermaid
flowchart TD
    A["refine_clip_x_range"] --> B{"layout_model 为可信双栏？"}
    B -->|是| C["按 caption 中心选择左栏/右栏边界"]
    B -->|否| D["跳过栏边界裁剪"]
    C --> E{"caption 本身窄于页面 60%？"}
    D --> E
    E -->|是| F["按 caption 位于左/右半页进一步限制另一栏"]
    E -->|否| G["跳过 caption 半页裁剪"]
    F --> H["收集 y 范围内对象"]
    G --> H
    H --> I{"对象 x union 合理且 caption 仍在候选内？"}
    I -->|是| J["按对象 x0/x1 加 padding 收窄"]
    I -->|否| K["保持现有 X"]
    J --> L{"宽度小于 page_width * min_width_ratio？"}
    K --> L
    L -->|是| M["围绕中心扩到最小宽度"]
    L -->|否| N["与页面相交后返回"]
```

可信双栏需要同时满足：

- `layout_model.num_columns >= 2`
- `column_gap > 0`
- `column_gap <= 30% page_width`
- 如果 margin 几乎贴页边，`column_gap` 不能超过 `25% page_width`
- 推导出的列宽不能小于 `20% page_width`

这避免单栏 PDF 被伪双栏裁成窄条。

## 9. Layout 版式裁剪

如果存在 `layout_model` 且未 no-refine，会调用 `adjust_clip_with_layout()`。它利用文本块、留白区域、栏信息对当前 clip 做版式层面的边界调整。

Table 在调用后额外执行 `restore_table_tail_after_layout_trim()`：

```mermaid
flowchart TD
    A["Table layout 调整后"] --> B{"layout 是否缩短了远端边界超过 min_tail_height？"}
    B -->|否| Z["保持 adjusted_clip"]
    B -->|是| C["构造被裁掉的 tail_clip"]
    C --> D{"tail_clip 是否 looks_like_table_text？"}
    D -->|是| E["恢复到 original_clip 的远端边界"]
    D -->|否| Z
```

该分支专门防止 layout far-strip 把表格内部数字行误当正文裁掉。

## 10. Table 行带识别

Table 额外调用 `refine_clip_to_table_band()`，从文本行识别连续表格行带，并只收紧 y 范围。

```mermaid
flowchart TD
    A["refine_clip_to_table_band"] --> B["收集 clip 内文本行并按 y center 分组为 rows"]
    B --> C["classify_table_row：strong / weak / none"]
    C --> D{"是否存在 strong row？"}
    D -->|是| E["weak row 需要数字证据、宽度约束或未来表格证据"]
    D -->|否| F["允许弱结构行组成表格，但至少 3 行弱证据"]
    E --> G["按方向从 caption 侧向远端扫描"]
    F --> G
    G --> H{"行距是否过大？"}
    H -->|是且不是强结构分组桥接| I["停止"]
    H -->|否| J{"当前行是 strong 或可信 weak？"}
    J -->|是| K["加入 selected"]
    J -->|否且已开始| I
    K --> G
    I --> L{"selected 是否足够？"}
    L -->|否| M["返回原 clip，changed=False"]
    L -->|是| N["用 selected union 得到 table_rect"]
    N --> O["按 table_rect 收紧远端 y 边界，changed=True"]
```

如果 `table_band_changed=True`，后续 Table autocrop 验收会更宽松：只要 autocrop 结果仍 `looks_like_table_text()`，即使高度比例偏低也可以保留。

## 11. Phase D：Autocrop

Figure 默认参数里 `autocrop=False`，Table 默认 `autocrop=True`。只要启用且未 no-refine，就进入像素裁剪。

```mermaid
flowchart TD
    A["Phase D：autocrop"] --> B["page.get_pixmap(dpi, clip)"]
    B --> C{"autocrop_mask_text？"}
    C -->|是| D["build_text_masks_px：遮罩近端或远端正文"]
    C -->|否| E["不遮罩"]
    D --> F["detect_content_bbox_pixels：基于白色阈值找像素内容 bbox"]
    E --> F
    F --> G["像素 bbox 转回 PDF pt 坐标"]
    G --> H["detect_far_side_text_evidence"]
    H --> I{"远端有正文证据？"}
    I -->|是| J["按 far_limit 限制 autocrop 远端边界"]
    I -->|否| K["保持 autocrop_clip"]
    J --> L{"当前是 Table 且 table_band_changed？"}
    K --> L
    L -->|是| M["跳过迭代远端正文裁切，保护表格行带"]
    L -->|否且 Figure| N["trim_far_side_text_post_autocrop"]
    L -->|否且 Table| O["trim_far_side_text_iterative"]
    N --> P["Figure：trim_far_side_noise_before_content 清理页眉线/噪声"]
    O --> Q["计算 autocrop_h、base_h、min_h_px"]
    P --> Q
    Q --> R{"高度是否满足 min_h 与 shrink_limit？"}
    R -->|是| S["final_clip = autocrop_clip"]
    R -->|Table 行带有效| S
    R -->|否| T["拒绝 autocrop，保留进入 autocrop 前的 clip"]
```

Figure 的 autocrop 后处理还会识别小写正文尾句，避免类似 `of such behaviors.` 被当作图内标题或内容保留。

## 12. Final 专用后处理

### 12.1 Figure final 图内标题回收

Figure 在 autocrop 后再次调用 `expand_clip_to_nearby_figure_title()`：

```mermaid
flowchart TD
    A["expand_clip_to_nearby_figure_title"] --> B["扫描被 final 裁掉但仍在参考 clip 内的邻近文本"]
    B --> C{"文本是否像页眉、caption、编号章节标题、同基线章节标题、小写正文尾句？"}
    C -->|是| D["跳过"]
    C -->|否| E{"是否为短图内标题 / chart title / 低字号标签？"}
    E -->|是| F["按方向扩展 final 边界"]
    E -->|否| D
```

它负责恢复 Gemini 图内 chart title、Kearns 轴标题等，但用负例规则避免恢复 Qwen 章节标题和 GPT-5 正文尾句。

### 12.2 Table final 宽度恢复

`restore_table_clip_width()`：

- 只有 `table_band_changed=True` 时生效。
- 如果 final 宽度小于 baseline 宽度的 `40%`，认为对象裁切把表格缩成局部列，恢复 baseline X 范围。

### 12.3 Table final 文本 bbox 安全补边

`expand_table_clip_to_text_bounds()` 是 Table final 的核心收口函数：

```mermaid
flowchart TD
    A["expand_table_clip_to_text_bounds"] --> B["先判断 final 是否 looks_like_table_text"]
    B --> C["_trim_far_side_body_prefix：裁掉已进入 final 的正文前缀/后缀"]
    C --> D{"final 原本不像表格且扩张后仍不像表格？"}
    D -->|是| E["只有能通过连通行或 layout 同排行恢复时才接受，否则返回原 clip"]
    D -->|否| F["_expand_far_side_to_connected_rows：回补连续表头/末行"]
    E --> F
    F --> G["_expand_far_side_to_layout_row：用 layout 同排 peer 回补缺失末行"]
    G --> H["_trim_far_side_to_first_structured_row：裁掉远端正文尾句或大空白"]
    H --> I["构造小范围 probe"]
    I --> J["按 text line bbox 做 x/y 小幅安全 padding"]
    J --> K["再次执行 _trim_far_side_to_first_structured_row"]
```

关键分支：

- 表格行判断可以接受多片段行、短数字行、短窄行。
- 但“正文后的安全起点”只接受 `part_count >= 2` 的强结构行，避免 `1/3 cases...` 这类数字正文被当成表格起点。
- 下方短换行尾行如果贴近多片段强结构行、宽度窄、词数少、不是章节编号，会作为表格单元格尾行保留。
- 宽长正文行作为 blocker，阻止连通行带跨正文段落扩张。

### 12.4 Table 远端章节标题裁除

有 `layout_model` 时，Table final 最后调用 `trim_table_far_side_section_heading()`：

```mermaid
flowchart TD
    A["trim_table_far_side_section_heading"] --> B["收集 layout title_ blocks 和 paragraph/list blocks"]
    B --> C["只看 final 远端区域内的 title_ 候选"]
    C --> D{"同一行带是否有表格单元格上下文？"}
    D -->|是| E["保留：可能是表头或数据单元格"]
    D -->|否| F{"附近是否有章节编号？"}
    F -->|是| G["视为章节标题候选"]
    F -->|否| H{"附近是否有多单元格表头上下文？"}
    H -->|是| E
    H -->|否| I{"后面是否跟满宽正文段落？"}
```

## 13. Refine Safe 验收与回退

Figure 和 Table 都有最终验收，但策略略有不同。

```mermaid
flowchart TD
    A["refine_safe 验收"] --> B["adaptive_acceptance_thresholds：按 baseline 高度和 kind 计算阈值"]
    B --> C["计算 height_ratio 和 area_ratio"]
    C --> D{"低于高度或面积阈值？"}
    D -->|是| E["accepted=False，记录 fallback_reason"]
    D -->|否| F["accepted=True"]
    E --> G{"final 宽度 < 页面 15%？"}
    F --> G
    G -->|是| H["hard_reject=True"]
    G -->|否| I["detect_text_pollution"]
    H --> I
    I --> J{"是否正文污染？"}
    J -->|Figure 污染| K["直接拒绝当前候选，continue"]
    J -->|Table 污染且不像表格| L["保存 rejected debug 后拒绝"]
    J -->|无污染或 Table 像表格| M{"accepted？"}
    M -->|是| N["通过"]
    M -->|否且 Figure 非 hard_reject| O["保留低比例精裁结果"]
    M -->|否且 Table 像表格且非 hard_reject| P["保留低比例表格精裁结果"]
    M -->|否且需要回退| Q{"Phase A 高度是否达标？"}
    Q -->|是| R["final_clip = clip_after_A"]
    Q -->|否| S["final_clip = base_clip"]
    R --> T["再次污染检测"]
    S --> T
    T --> U{"回退结果是否污染？"}
    U -->|是| V["拒绝候选"]
    U -->|否| N
```

Figure 的低比例策略较软：只要不是硬拒绝且没有正文污染，会保留 refined clip，避免把正文重新带回 baseline。

Table 的低比例策略更依赖 `looks_like_table_text()`：如果 final 虽小但仍像表格，可以保留；如果不像表格且污染，则拒绝。

## 15. Figure 与 Table 的核心差异

| 阶段 | Figure | Table |
| --- | --- | --- |
| 默认方向 | `above` | `below` |
| 局部方向评分 | 主要看对象覆盖率 | 优先用表格文本结构，再看对象覆盖率 |
| baseline 补偿 | 图内标题回收 | 多行表头回收 + 渲染横线补偿 |
| Phase A | 相邻正文和远端正文裁切 | 跳过 adjacent sweep，保护表头 |
| Phase B | 保护小对象带、竖排标签、轴标题、near-caption 图内标注 | 支持水平并列对象 union |
| X 收窄 | 栏位/对象 x union | 同 Figure，但后续可恢复宽度 |
| Layout 后处理 | 普通 layout 调整 | layout 裁尾后可按表格文本恢复 |
| 行带识别 | 无 | `refine_clip_to_table_band()` |
| Autocrop | 默认关闭，开启后有 Figure far-side 噪声清理 | 默认开启，表格行带有效时放宽验收 |
| Final 后处理 | 图内标题二次回收，小写正文尾句排除 | 宽度恢复、文本 bbox 补边、正文前缀裁除、章节标题裁除 |
| 验收 | 低比例非硬拒绝时偏保留 | 低比例必须像表格才偏保留 |

## 16. 当前设计原则

这套流程的稳定性来自三个约束：

1. **Caption 是锚点，但不是唯一证据。** caption 先决定候选窗口，后续还要用对象、文本行、layout block 和像素内容交叉验证。
2. **裁剪只在有明确证据时推进。** 能识别正文、章节标题、相邻 caption 时才收紧；能识别图内标题、表头、末行时才补回。
3. **Figure 与 Table 分流。** Figure 更看重对象和图内标签，Table 更看重文本行带和多单元格结构。很多规则只在对应路径启用，避免互相干扰。
