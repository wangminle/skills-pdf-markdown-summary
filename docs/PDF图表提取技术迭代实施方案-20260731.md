## 1. 背景与结论链

四份依据文档构成一条「提出 → 验证 → 修正」的演进链，最终结论高度收敛：

1. **0721 根因复盘**：仅靠 caption/排版启发式在开放世界无法保证 99%；路线应从「找更完美的规则参数」转向「多证据候选 + 模型粗定位 + PDF 几何精修 + 置信度承认不确定性」。
2. **0728 可行性实验**：PyMuPDF4LLM Layout 在 basic-benchmark 8 份 PDF 上验证了工程可用性（0.68 s/页纯 CPU，8/8 跑通，picture/table/caption 语义框可用）。
3. **0728 对比分析**：Layout 与 legacy 硬失败率接近（7.8% vs 5.6%）但**失败模式几乎不重叠**（legacy：混正文/配错页/正文引用；Layout：漏检/多 panel 拆碎），融合上限明显高于任一方。
4. **0728 二次复核（最严口径）**：推翻了两个表面数字——95.6% 只是候选覆盖率（配对器允许一框多配，8 组重复框涉 16 条资产）；Layout 对 GT 的指标是自证（GT 由 Layout 自身生成）。当前一切准确率数字都不能宣称。

**技术路线最终判断**：

> 不做「Layout 替换 legacy」，做「**Layout 供证据 + 全页一对一配对 + 现有规则降级为小幅精修 + 冲突进人工复核**」的融合架构。

## 2. 产品验收口径（本轮迭代的最高优先级约束）

本节将产品目标固化为可计算、可验收的定义，后续所有架构决策与指标阈值以本节为准。**本节任一条目在 A0 结束前如需修改，必须先改本节再改代码。**

### 2.1 验收标准（用户口径原文）

- 图和表的**留白区域过大是可以接受的**；
- **偶尔可以接受一行以内的混正文**；
- **不接受错漏截图**（截断、把正文/引用当成资产、配错页）；
- **不接受漏检**；
- 核心目标：**导出的图和表与文档中 Figure/Table 的数量对齐**；
- 留下的图里**必须能看到所有完整信息**。

### 2.2 形式化为四类结果

**共同前提：四类结果一律导出图片文件。** 用户口径是「不接受漏检 + 留白可接受」，因此不确定时的正确行为是**导出一个偏保守的大框并打标**，而不是不导出。任何一条资产在 `index.json` 中缺少 `out_path`，都直接计入漏检。

| 结果 | 定义 | 处置 |
| --- | --- | --- |
| `accepted` | 覆盖完整（通过 §2.5 截断判据），无混正文或仅边缘 ≤1 行 | 自动导出，正常写入 Markdown |
| `accepted_with_margin` | 覆盖完整，但留白偏大 | 自动导出，正常写入 Markdown（**这是常态结果，不是次等结果**） |
| `review_required` | 配对冲突、跨页不确定、覆盖或方向置信不足 | **仍导出**多源并集的保守框（宁可留白），同时置 `review_required=true`、写 `warnings`、产出 debug overlay 与候选框清单 |
| `rejected` | 检出了 caption 但无法产出任何可信内容框 | **仍导出**兜底框（caption 邻域保守窗口），置 `review_required=true` 并记 `reject_reason`；计入漏检风险统计 |

> 说明：`rejected` 与 `review_required` 的区别只在于是否存在内容框证据，两者对用户的可见行为一致（都有图、都带告警）。这样「数量对齐率」这一 KPI 才是可计算的。

### 2.3 硬失败定义（任一发生即为缺陷，必须变红）

**四类，缺一不可。** v1 只列三类，导致「整页截图」这种退化解在口径上完全合规（覆盖满、零截断、零漏检、purity 不设阈值），第 4 类是防退化的唯一护栏。

1. **漏检**：文档真实存在的 Figure/Table 没有任何对应导出资产（含 `index.json` 有条目但无图片文件）；
2. **错配**：导出资产配到错误页、错误对象，或把正文引用/正文段落当成资产主体；
3. **截断**：导出截图丢失图表主体的任何可见信息（图内标题、轴标签、panel、图例、表头、末行、footnote 等）；
4. **过量混正文**：框内非资产正文文本行 **>1 行**。

### 2.4 明确不算失败的项

- 留白/白边偏大（对应实验中 56 例 `legacy_loose`，是产品口径而非缺陷），**面积不设上限**，退化由第 4 类硬失败约束；
- 截图边缘混入 **≤1 行**正文。"一行"的操作性定义：单个文本行（PyMuPDF `line` 粒度），高度不超过该页正文行高的 1.3 倍，位于资产框上/下边缘，且与图表主体对象的 bbox 无交叠。

### 2.5 截断判据：二值，不用面积比例

v1 用 `coverage ≥ 0.99` 表达「不许截断」，两者不等价：一条轴标签、一行表尾、一个 footnote 的面积往往远小于图表面积的 1%，coverage 能轻松通过而信息已经丢了。因此拆成两层：

| 层 | 判据 | 用途 |
| --- | --- | --- |
| **判定层（决定合格与否）** | GT 标注的**每一个**构成元素（对象 bbox、文本行、图内标题、panel、表头、末行、footnote）是否被预测框完整包含（允许 ≤1pt 的浮点容差） | 二值。任一元素被切即判第 3 类硬失败 |
| **筛查层（决定看哪些）** | content coverage = GT 与预测交集 / GT 面积（多 bbox 取并集），阈值 **≥0.995**（沿用 0721 报告 §七.1 的 safe success 口径） | 连续量，用于自动排序、抽样和趋势监控，**不单独作为合格判据** |

### 2.6 指标定义（按本口径重排优先级）

| 指标 | 定义 | 目标地位 |
| --- | --- | --- |
| 数量对齐率 | 导出资产数与真实 Figure/Table 数的对齐比例（漏检、多检分别统计） | **首要 KPI** |
| 截断率 | 触发 §2.5 判定层的资产占比 | **首要 KPI**，目标 0 |
| 配对正确率 | caption 与正确 asset group 的一对一配对准确率 | **首要 KPI** |
| 过量混正文率 | 框内非资产正文行 >1 行的资产占比 | **首要 KPI**，目标 0 |
| content coverage | GT 与预测交集 / GT 面积 | 筛查指标，阈值 ≥0.995（见 §2.5） |
| crop purity（宽松口径） | GT 与预测交集 / 预测面积 | 参考项，**不设硬阈值**；空白不罚，仅用于观察趋势 |
| review_required 比例 | 带告警导出的资产占比 | 过程指标，用于权衡自动化程度；不设硬阈值，但需逐版本记录 |

> 与 0721 报告 §七.1 的对应关系：本口径实质是把 **safe success（宁可留白不截断）定为唯一成功口径**，strict purity 退出验收。`strict success`（coverage≥0.98 且 purity≥0.95）不再作为目标。

## 3. 目标架构

以二次复核 §8.4 的五层结构为准，并按第 2 节口径调整各层职责：

```text
L0 页面解析与缓存
    每页只做一次文本/图像/drawing/渲染/版式数据准备；
    Layout 结果按 PDF hash + 后端版本 + 参数版本缓存，
    避免两条流水线耗时简单相加（实测串行约 1.25 s/页）。

L1 多源候选生成（并行、互不依赖）
    A. PyMuPDF4LLM Layout：picture / table / caption 语义框
    B. 现有 caption 正则 + 评分（保留，仍是强锚点）
    C. PyMuPDF 原生：image blocks / drawings 连通域 / find_tables / Tagged PDF

L2 全页资产识别与一对一配对        ← 真正的难点，独立成层
    - 正文引用过滤：caption 邻域有无 content 框（实测 8/8 命中）
    - 完整多行 caption bbox（不只取首行）
    - 同页 caption/content 序列对齐（不逐 caption 独立判方向）
    - 一个候选框最多分配一次；支持一个 caption 对多个 content bbox
    - 编号连续性约束；continued/跨页/共享 caption 建显式 group
    - 无法唯一求解 → review_required（仍导出保守并集框），不伪造成功

L3 Figure/Table 专用小幅精修（按 §2 口径调整方向）
    - 以 L1/L2 候选框为种子做小幅校正，不再从大窗收缩
    - 校正方向偏"包全"不偏"收紧"：宁可留白，不冒截断风险
    - 唯一的收紧动力来自 §2.3 第 4 类硬失败（>1 行混正文），
      即"只在能确认是正文行时才收"，不确定一律保留
    - 复用现有最成熟资产：对象边缘 snap、图内标题/panel label 回补、
      像素白边裁剪（保守强度）、表头/末行/横线/footnote 恢复、
      caption 剔除、页眉页脚过滤、debug stages

L4 置信度、验收与复核
    - accepted / accepted_with_margin / review_required / rejected（四者均导出图片）
    - 多源一致 → 高置信直出；源间 IoU 过低或方向冲突 → review_required
    - Layout/原生候选不足但旧规则有可接受结果 → legacy fallback 后按上述四态定级
```

对 0721 报告的两处修正（已被实验证实，纳入本方案）：

1. Layout 定位从「候选生成后端」升级为「**独立证据源**」——交叉验证与冲突检测价值大于单纯产候选框；
2. 精修从「大窗收缩」降级为「**候选框为种子的小幅校正**」——实验显示 Layout 框贴合度普遍优于 legacy 精修后结果（legacy 空白率均值 22.8%），且本口径下「框偏松」不是缺陷。

### 4.1 A0-4 人工标注的可执行细节

v1 只写了「格式支持多 bbox」，落地会卡在工具和规范上，这里定死：

| 项 | 约定 |
| --- | --- |
| 工具 | LabelMe（本地、轻量、矩形标注）在实验已产出的整页渲染图上标注；渲染 DPI 与 `01_extract_layout.py` 保持一致，转换脚本 `tests/eval/convert_labelme_to_gt.py` 负责像素坐标 → PDF 点坐标 |
| 存放 | `tests/annotations/<pdf-stem>/gt.json`；schema 说明与标注规范写在 `tests/annotations/SCHEMA-20260731.md` |
| 单条字段 | `document_id`、`kind`、`ident`、`caption_page`、`occurrence`、`group_id`、`caption_bbox`、`content_bboxes[]`、`elements[]`（截断判定用的构成元素清单）、`ambiguous`、`ambiguity_reason`、`annotator`、`reviewer`、`annotated_at` |
| 标注规范需逐条给正反例 | ①图内标题算资产主体；②figure footnote / table note 算资产主体；③多 panel 共享 caption 时每个 panel 单独一个 bbox，`group_id` 相同；④跨页 continued 分两条记录，`group_id` 相同；⑤正文引用不标，另记入 `false_caption` 清单用于验证正文引用过滤 |

## 6. 风险与约束

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 依赖体积 | pymupdf4llm 拉入 onnxruntime 约 42.5MB | 独立 `requirements-layout.txt`；主链在依赖缺失时静默降级 |
| 许可证 | PyMuPDF 系列为 AGPL | 分发方式需结合实际产品形态法务确认；后端可插拔设计降低绑定 |
| 耗时叠加 | 两条流水线串行约 1.25 s/页 | L0 共享页面解析 + 缓存；离线批处理可接受 |
| 评测污染 | basic-benchmark 是长期调参语料 | 仅作 dev/回归集；一切结论外推等 A4 holdout |
| golden 冻结缺陷 | 基准由当前输出生成，会把已知缺陷一并冻结 | 明确 golden 是本地变更检测器；基准更新后在 `task-list.md` 逐条说明 |
| 回退风险 | A3 触及主链核心 | feature flag + golden 回归（含 bbox）+ 旧路径保留为 fallback，缺一不可 |
| 配对复杂度 | 边权仍需人工确定，配对图不自动消除调参空间 | 参数由 A0/A4 的 GT 与指标约束，而非凭经验 |
| 标注主观性 | 「构成元素」清单直接决定截断判定 | 标注规范给正反例；双人复核；歧义条目单独统计 |

## 7. 明确不做的事

1. **不直接用 Layout 替换现有链路**——多 panel/组合图上 Layout 退化，legacy 反而稳；
2. **不引入 YOLO / 版面检测大模型 / 通用 VLM 主链**——0.68 s/页纯 CPU 已够用，本语料看不到重模型边际收益；
3. **不基于现有实验宣称任何准确率数字**——GT 半自动且有假阳性，语料是调参集；
4. **不继续以新增 pt/宽度比/字符数阈值作为主要路线**；
5. **不强制每个 caption 输出单页单矩形**；
6. **不让任何一类结果「不导出图片」**——不确定时导出保守框并打标，而不是留空（见 §2.2）；
7. **不通过放松 §2.3 硬失败定义来达成 KPI**；
8. **不在 A0 退出条件达标前开工 A1**（0721 报告原 Phase 1 即因跳过评测建设而被二次复核修正）。
